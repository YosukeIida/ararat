# Arc と Ardia の観察: フローティングサイドバー（2026-10-31 時点）

この文書は `arc-ardia-observed.md` の日本語訳である。内容が食い違うときは英語版に従う。Yab の値と計測の方法: `yab-observed.ja.md`、`yab/README.ja.md` の 4 節。計測には同じ道具と同じディスプレイを使った（3440×1440 のディスプレイ 1 枚、倍率 1×、165 Hz、macOS 27.0.1）。時間は、マウスのイベントを送ってからフレームの callback までの時間であり、別に計測していない取り込みの遅延を含む。サイドバーを隠した状態にし、サイドバーの端が見分けられるように白いページのテスト用のタブを開いた。どちらも計測の後に元に戻した。

対象: Arc 1.171.0（サイドバーを隠した状態。View › Show Sidebar）、ウィンドウは 1146×1410 pt。Ardia 0.2.42（View › Auto-Hide Tabs をオン）、ウィンドウは 1360×860 pt。

## 3. Ararat への示唆

- Arc についてのオーナーの記憶は正しい。ポインタがウィンドウの左外側へ出ても、Arc はポインタがウィンドウからおよそ 250 pt 左に離れるまでサイドバーを表示し続け、それより離れると隠す。Yab も左外側では表示を続けるが、どこまで離れると隠れるかは計測していない。Ararat はこの点で Arc の規則に従う（オーナーの選択、2026-10-31）。切り分けていないこと: 250 pt がサイドバーの幅に依存するか（ウィンドウの幅には依存しない。4 節）、計測したウィンドウの左側が別の Arc のウィンドウであったことが影響するか。Ardia はそうではなく、どの方向でもウィンドウを出ると隠れ、ウィンドウの外からは現れない。
- ウィンドウの上とアプリが非アクティブになったときに、Arc と Yab は異なる。Arc はどちらでも隠れ、Yab は残る。オーナーは Arc の値と、この 2 つの規則の両方を選んだ（architecture §7）。
- Arc は Yab より早く反応し（とどまる時間はおよそ 150 ms、領域は 5 pt。Yab は 330 ms と 12 pt）、右への余裕も広い（およそ 72 pt。Yab は 38 pt）。
- Ardia のフローティングサイドバーは、ウィンドウ内だけのホバーに待ち時間を付けたものである。ウィンドウの外の規則については、Ardia のコードは参考にならない。

## 4. Arc の追加の計測

- **ばね。** 表示の計測 6 回分の全フレームに減衰振動のばねを当てはめると、response は 154 ms（標準偏差 10）、damping は 0.84（標準偏差 0.02）となり、誤差の rms は 1〜4 px であった。architecture §7 の出典（components note 5）の値（0.185 s、0.77）は、6 回すべてで当てはまりが悪かった。行き過ぎ（177 px のうち 2 px）だけでは damping を推定するには小さすぎるため、曲線全体に当てはめた。
- **隠れる距離。** ウィンドウの左端から測ると、サイドバーは左へおよそ 250 pt（250 では残り、252 では隠れる）、右へおよそ 257 pt（256 では残り、258 では隠れる）で隠れる。左の限界は、ウィンドウの幅が 800、1146、1600 pt のいずれでも同じであった。左右の限界は、ウィンドウの左端からの 1 つの距離である可能性がある。サイドバーの幅は変えていないため、その距離がサイドバーの幅に比例するかは分からない。
- **画面の左端に接したウィンドウ。** ウィンドウを x = 0 に置くと、ポインタが 0〜4 pt でサイドバーが現れ、0 pt に置いたままでは表示が続く（3 s 計測）。

## 5. サイドバーの上のスクロールによる space の切り替え

2026-10-31 に、ナチュラルなスクロールをオンにした状態で、Arc、Yab 0.42.1、Ardia を計測した。装置は Magic Trackpad と、スクロールモードを持つトラックボールである。オーナーが Arc と Yab のサイドバーの上で各装置を操作し、動いた space を報告した。同じイベントを `scrollrec` でシステム全体から記録し、記録した 14 のジェスチャー（ホイール 5、トラックパッド 9）を `scrollplay` で中央の space から各アプリに再生した。合成したイベントは `scroll` と `lineprobe` で送った。space の読み取りと復元には AppleScript を使った。ツールは `yab/` にある（README の 4 節）。以下では、向きを手の動きではなく横のデルタ（`scrollingDeltaX`）の符号で書く。オーナーの「右に移動」は、右隣の space へ移ることとも、中身が右へ動くこととも読めるため、どの手の動きがどの符号になるかは確定していない。

**装置が送るもの。** どちらの装置も、方向の反転の印（CGEvent のフィールド 137、`NSEvent.isDirectionInvertedFromDevice`）を立てる。同じ手の動きは、どちらの装置でも同じ符号になる。符号だけに従う Yab が、オーナーの操作で 2 つの装置とも同じ向きに動いたからである。トラックボールはフェーズの無いホイールのイベント（`isContinuous` 0）を送る。1 回のフリックは 90〜180 ms の間の 7〜12 イベントで、OS の加速によりデルタは 1 イベントあたり 15〜20 行まで増える。トラックパッドは、フェーズ付きのイベント（may-begin、began、changed、ended）の後に、0.8〜1.6 s の慣性のイベントを送る。

| 同じ手の動き | Arc | Yab | Ardia（再生のみ） |
|---|---|---|---|
| トラックボールとトラックパッド | 逆の向き | 同じ向き | 同じ向き |
| トラックボールの強いフリック | 1 つ | 2 つ（記録した 5 回のフリックすべて） | 1 つ |
| トラックパッドの強いフリック | 1 つ | 1 つ | 1 つ |

再生の結果はオーナーの報告と一致した。Arc では、遅いトラックパッドのドラッグ 1 回が動かなかったほかは、記録したすべてのジェスチャーで 1 つ動いた。Ardia ではすべてのジェスチャーで 1 つ動いた。Yab では、ホイールのフリックはすべて 2 つ、トラックパッドのジェスチャーはすべて 1 つ動いた（遅いドラッグは動かなかった）。

**向き。** Arc は、トラックパッドでは負のデルタで次の space へ進む。ホイールでは、反転の印が立っているときに符号を反転してから、負なら次の space へ進む。合成したイベントで印を立てると、Arc のホイールの向きだけが反転し、トラックパッドの向きは変わらなかった。そのため、ナチュラルなスクロールのもとでは、同じ手の動きでも、2 つの装置で Arc の space は逆に動く。Yab は印を無視する。Ardia もホイールのイベントを印で反転するが、印の無いときのホイールの向きが Arc と逆であるため、ナチュラルなスクロールのもとでは 2 つの装置で同じ向きに動く。

**Arc のホイールの規則**（`scrollplay` で送った合成の単発と 2 連のイベント）。Arc は、短い時間の窓の中で固定小数点のデルタ（行単位のイベントの `scrollingDeltaX`）を合計する。1.0 のイベント 1 つでは切り替わらず、1.2 では切り替わる。1.0 のイベント 2 つは、40 ms 間隔なら切り替わり、50 ms 以上の間隔では切り替わらない。切り替えの後はホイールの入力を無視する。切り替えの 230 ms 後の強いイベントは無視され、260 ms 後のイベントで再び切り替わった。休止は、最初のイベントからではなく切り替えから数える。40 ms の 2 つ目のイベントで切り替わった場合、270 ms のイベント（切り替えの 230 ms 後）は無視され、310 ms のイベントで切り替わった。イベントが続いても休止は延びない。30 ms 間隔の 1 行のイベントの列は、10 イベント（最後がおよそ 270 ms）で 1 つ、12 イベント（およそ 330 ms）で 2 つ、16 イベント（およそ 450 ms）で 2 つ動かした。実機のフリックは 180 ms 以内に終わるため、1 つしか動かない。Ardia も同じイベントの列で同じ数だけ動いた。Yab は、2〜4 イベントで 1 つ、6 または 8 で 3 つ、12 で 5 つ動いた。250 ms よりずっと短い間隔で再び切り替わる。Yab の規則はそれ以上計測していない。

**Arc のトラックパッドの規則**（`lineprobe` でフェーズ付きのイベントを送りながら、サイドバーの 1 画素の行を最大 240 fps で記録した）。サイドバーはジェスチャーに追従する。各イベントはサイドバーをデルタの半分だけ動かし（−4 で左へ 2 pt）、隣の space はおよそ 180 pt 離れて並ぶ。離したとき、Arc はおよそ直前 100 ms の動きを見る。動きがあれば、その向きの space を選ぶ（−1 を 16 ms 間隔で 3 回送って離すと切り替わった。−2 を 3 回送り、60 ms 止めて離すと切り替わり、120 ms 止めると切り替わらなかった）。直前の動きが無ければ、近い方の space を選ぶ。90 pt（デルタ 180）で止めると元に戻り、92 pt で切り替わった。これは 180 pt の間隔の半分にあたる。離した後の慣性のイベントでは、それ以上動かない。切り替えの後の静止は、response およそ 250 ms、damping 0.88 の spring に当てはまる（rms 1.5 pt）。切り替えずに戻る動きは、およそ 190 ms、0.98 に当てはまる（rms 1.1 pt）。

**リストの端。** 最後の space より先では、サイドバーはラバーバンドで動く。デルタ 600 で約 38 pt 動き、途中の点は、`x` をデルタの半分とした `255·(1 − 1/(0.15·x/255 + 1))` と数 pt 以内で一致した。そこで離すと、Arc の「Create a Space」の画面が開いた（space は作らず、最後の space に戻した）。最初の space の手前には Library がある。同じドラッグで Library の画面が滑り込み、離した後も Library のままであった。

これらの値は、公開されている Dia の値（`arc-dia-components.ja.md` の 5.3 節、profile paging）と一致する。デルタの半分、同じラバーバンド、1 を超える 49 ms のホイールの窓、0.25 s の休止、100 ms の速度の履歴である。Dia の静止の spring は 0.25 s の臨界減衰であり、Arc に当てはめた damping は 0.88 であった。

計測していないもの: 縦のホイールの入力（斜めのトラックボールの操作は再生し、横の成分と同じように振る舞った）、90 pt の閾値がサイドバーの幅に比例するか。

## 6. Arc のその他の動き

ドックしたサイドバー（ウィンドウ 1146×1410 pt、サイドバーの幅およそ 180 pt）で、同じ方法で計測した。

| 操作 | 計測した値 |
|---|---|
| ドックしたサイドバーを隠す（⌘S） | ページの左端は、キーのおよそ 50 ms 後に動き始め、およそ 90 ms で 168 pt を ease-out で動く。91 ms の ease-out cubic（rms 2.2 pt）、または response 103 ms、damping 0.89 の spring（rms 2.1 pt）に当てはまる。3 回 |
| 表示する（⌘S） | 3 回とも、キーの 555〜585 ms 後に動き始め、およそ 100 ms で 168 pt を ease-out で動く。99 ms の ease-out cubic（rms 1.8 pt）、または 122 ms、0.83 の spring（rms 1.2 pt）に当てはまる。遅れの理由は分かっていない |
| タブを開く | 新しい行は Today の先頭に入り、下の行は 1 行分下へ動く。最初の 28 pt におよそ 40 ms かかった。動きの終わりは追跡できなかった |
| タブを閉じる | 下の行は 1 行分（およそ 41 pt）上へ動く。117 ms の ease-out cubic に当てはまる（3 回で rms 0.3 pt）。リストの末尾の行を閉じると、その行はおよそ 110 ms で消える |

アクセシビリティの API で読んだ View メニューの Show/Hide Sidebar の項目は、サイドバーの状態と一致しないことがあった。サイドバーの状態は画面で確かめた。

## 7. 閉じた後に選ばれるタブ（2026-11-01）

Arc 1.171.0 で、この計測で作ったタブ（example.com）を使って計測し、閉じた（Arc はそれらを archive に入れた）。初めは別のアプリが前面にある状態で Arc の AppleScript の `close tab` を使い、次に Arc を前面にして ⌘W を使った。どちらも同じ結果であった。

- Y4、Y2 の順に選んで Y2 を閉じると、Y2 の隣の Y1 や Y3 ではなく、Y4 が選ばれた。
- Y1、Y3、Y4 の順に選んで順に閉じると、Y3、Y1、Y1 の前に選んでいたタブの順に選ばれた。選択の履歴である。
- 別の space でタブを開いて閉じると（その space には pinned のタブしかなく、それまで何も選んでいなかった）、何も選ばれず、その space にとどまった。履歴は space をまたがず、pinned の隣のタブも選ばれなかった。

## 8. サイドバーでのドラッグと整理（2026-11-03）

Arc 1.171.0、1× のディスプレイで計測した。タブとフォルダは計測のために作り、計測の後に片付けた。操作は合成したマウスのイベント（押す、8 ms ごとに動かす、離す）で行い、ウィンドウを撮影した。

- タブの行を押すと、そのタブが選ばれ、ドラッグは選んだタブを運ぶ。
- ドラッグの間、元の行は塗りを付けたままその場に残り、行の写し（塗り、favicon、タイトル、✕）がポインタに付いて動く。他の行は間を空けない。落とす位置は、ほぼ白の 2 pt の線で示す。線は幅およそ 178 pt のサイドバーの x 16 から x 166 まで引かれ、左端に直径およそ 7 pt の中空の輪が付く。線は 2 つの行の境目（41 pt の間隔で、行の中心から 20.5 pt）に置かれる。
- 離した後、写しはおよそ 100 ms で収まる（縦の 1 本の線の画素の変化は、離してからおよそ 120 ms で止まった）。
- Today のタブを区切り線より上へドラッグすると、その位置でピン留めになる。選ばれたピン留めの行には、タイトルの下に「Double-click to rename」と出る。ピン留めのタブを区切り線より下へドラッグすると、ピン留めが外れる。
- フォルダの行の上では線は出ず、そこで落とすとタブはフォルダの中（1 段の字下げ）に入り、フォルダが開く。
- お気に入りの上では、ドラッグの間にタイルが並び直す（2 個のタイルが 3 列になり、落とす場所に空のタイルが出る）。落とすとタブはお気に入りになる。お気に入りのメニューの Remove Favorite はタブを閉じ、Today には戻らなかった。
- フォルダは、+ のメニュー（New Space、New Folder、New Easel、New Boost、New Split、New Tab）か、サイドバーの空いた所のメニュー（space の項目、New Folder、Live Folders）から作る。新しいフォルダ「Untitled」はピン留めの末尾に加わり、タイトルが名前の変更の状態になる。空のフォルダの Delete は、確認なしで消した。
- メニュー: Today のタブのメニューは、Copy Link、Share、Change Icon…、Rename…、Mute、Customize Page…、Open in Split View、Duplicate、Move to（space の一覧と New Space…）、Archive Tab、Archive Tabs Below である。ピン留めのタブのメニューは、Open in Split View の代わりに Add Split View を置き、Edit Pinned Page を加え、アーカイブの項目の代わりに Remove Pin で終わる。お気に入りのメニューは Close Tab（⌘W）と Remove Favorite で終わる。フォルダのメニューは、Share Folder…、New Nested Folder…、Turn into Space、Change Icon…、Rename…、Duplicate、Move to、Delete である。タブのメニューには新しいフォルダの項目が無いので、Arc には Today にフォルダを作る手段が無い。
- 合成のドラッグではフォルダの行のドラッグが始まらなかった（押すたびにフォルダが開閉した）。オーナーが手で確かめた（2026-11-03）: フォルダは Today にもお気に入りにもドラッグできず、ピン留めの中にだけ置ける。タブの入ったフォルダを削除すると、先に確認が出る。「Delete your “<名前>” folder?」と「Deleting this folder will archive the tabs inside it.」に、Cancel（Esc）と赤い Delete Folder（Return）が付き、確定すると中のタブをアーカイブする。
- オーナーが目で確かめたこと（2026-11-04）: 「Double-click to rename」は、タブを Today からピン留めに移した直後の数秒だけタイトルの下に出る。ピン留めのタブを選んだだけでは出ない。名前の変更の欄は選んだ文字だけを示し、フォーカスリングは出ない。Create a Space の名前の欄は、フォーカスリングの無い暗い角丸のカードである。表示の時間は計測していない。
- まだ計測していないこと（オーナーが計測を希望）: ドラッグしたタブを閉じたフォルダの上に置いてから、フォルダが開くまでの時間。別の space のドックの点へのドラッグは試していない。
