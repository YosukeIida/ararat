# Ledger of Ardia's design decisions

Translated from `ardia-ledger.ja.md` (2026-10-30). The English file is the source of truth from now on.

Subject: mantrakp04/ardia (GPL-3.0). Read via `gh api`: main as of 2026-10-30, and the documents as of commit `2713787d`. The code was not read and not copied. Only the decisions and their reasons were taken.

Terms:
- **ArdiaCore**: a framework built by putting an in-house layer `//ardia/core` into Chrome's own `//chrome:chrome_framework`. Same approach as Dia's ArcCore.
- **In-house layer**: `//ardia/core` (`engine/ardiacore/src`) and `//chrome/browser/ardia` (`engine/chromium/src`). Both live in the repo and are copied into the tree by `apply.sh`.
- **hook**: a `g_ardia_*` function pointer placed in a Chrome file. If unset, Chrome runs unmodified.
- **store**: the zustand state on the React Native side. It holds the workspace (sidebar order, pins, groups, splits).
- **review**: `docs/architecture-review.md` of 2026-10-01 (exists only at `2713787d`).

## 1. Decision ledger

Applicability column: Adopt / Reject / Open. It states how each decision applies to Ararat (Swift/AppKit UI, the ArcCore approach of placing an in-house layer in a Chromium fork, a Rust core, Windows/Linux/iPhone later).

### 1.1 Engine embedding (CEF → ArdiaCore)

| Decision | Reason | Rejected alternatives | Evidence | Applies to Ararat |
|---|---|---|---|---|
| Drop CEF, link the in-house layer into `//chrome:chrome_framework`, and implement an in-house `BrowserWindow` (a plain object with no `BrowserView`, frame, tab strip, or toolbar) | CEF forces three structural conflicts. (1) A Chrome-style CEF browser is itself a Views widget window, and the window layer was rebuilt twice in two weeks. (2) A mechanism was needed to intercept, via callbacks, and adopt tabs that Chrome creates by itself (`window.open`, extensions, `chrome.windows.create`), and POST bodies were lost. (3) With the external message pump, autofill ignored clicks and a 30 Hz idle poll was required. In the previous week, 42% of app and engine commits and 56% of fix commits touched the CEF/Chrome seam, and 77% of engine patch lines existed only to pass Chrome objects through CEF's API | Keep extending CEF's API. Make TabStripModel the single source of truth. Alloy (no `Browser`). An OWL-style out-of-process host (ChatGPT Atlas). Rewrite the UI in SwiftUI/AppKit | review › Recommendation 5, § A, § B | Adopt. Start with the ArcCore approach from the beginning, without going through a CEF stage |
| The migration is a strangler, but not "per window type"; instead "build a second native implementation behind the same JS API and switch over at once on parity" | CEF and ArdiaCore are both full Chromium and cannot coexist in one process. The spike found the review's original plan (one type at a time, starting from Little Ardia) impossible | Replace window types one at a time inside one app | ardiacore-spike.md › Verdict at the top, › Codex second opinion | Adopt (as a lesson). If the core API is decoupled from the UI, swapping engines is just exchanging the implementation behind it |
| Chromium owns the process run loop (`ChromeMain` → `MessagePumpNSApplication` → `[NSApp run]`). `NSApp` is Chrome's `BrowserCrApplication`, and the RN host starts inside it | The external-pump defects (idle work not running, a poll to get wakeups from 41 → 15/s) disappear at the root. Dia's Swift UI uses the same structure | Go back to `CefRunMessageLoop` (described as a medium-sized job requiring a redesign of shutdown) | review › Recommendation 5 (3), § G, agent-brief.md › Stack | Adopt. But treat it as a constraint: touch `NSApp` only after Chromium has started. Design the Swift/AppKit UI to be brought up inside Chromium's loop as well |
| Do not create Chrome's `AppController`; stand in a substitute that receives `terminate:`, Dock, and logout quit Apple events itself, and implement cancellable close/quit that goes through beforeunload and download confirmation | CEF's patches had removed `AppController`; without it the app cannot stay alive with no windows, and the `terminate:` path also breaks. When a page cancels a quit, keep-alive must be held | Use Chrome's `AppController` as is | ardiacore-spike.md › Stage 1 runtime, › What the spike does not prove | Adopt. Put it in the design from the start, as a responsibility that always arises when owning an in-house `BrowserWindow` |
| One app window = one `ArdiaCoreWindow` (a Views-backed `NSWindow`). Multiple per-profile `Browser`s are attached to it | Chrome's bubbles, dialogs, menus, and autofill dropdowns attach to that window as child windows. Switching profiles becomes swapping a view, eliminating the old `MoveRoot` (15–25 ms on the main thread per switch) and per-profile Chrome windows | A Chrome window per profile (the 0.2.0 approach; full screen needed an auxiliary child window) | agent-brief.md › Stack, ardiacore-spike.md › What was built, review › Recommendation 5 (1) | Adopt. Codex also agrees that a widget-backed window is a cheap way to attach Chrome's bubbles |
| Popups, `target=_blank`, and ⌘-click take the `WebContents` and navigation that Chrome created as is, and rewrite them into tabs of the in-house `Browser` | `Browser::AddNewContents` hands over a `WebContents` that is already created and already navigated (including POST), so neither adopt nor replay is needed | CEF's `OnBeforePopup` → JS → adopt by id (30 s orphan timer); `StrayWindowClient`, which hides windows Chrome created on its own and replays the URL | review › Recommendation 5 (2), ardiacore-spike.md › What was built › Popups | Adopt |
| Windows that Chrome creates by itself (`chrome.windows.create`, incognito, undocked DevTools) query the host via a hook in the `Browser` constructor and are housed in in-house windows | Left alone, a Views `BrowserView` window appears | Make every `Browser` creation path in-house | ardiacore-spike.md › Stage 1 runtime (S5), perf/vs-browsers.md › New window | Adopt. However, in Ardia a parity defect in which new windows get absorbed into an existing window remained as of 2026-10-16 |
| The entry point to the in-house layer is plain C: every export is `ac_<domain>_<verb>` with the same signature (profile dir, JSON arguments, reply callback). The app looks them up with `dlsym` and aborts if any is missing. Only the engine side decides whether calls into a private profile are allowed | Removes the burden of needing a CEF header, translator, wrapper, and marker for every new capability. The app and engine ship together, so a missing export is treated as the error "shipped an unexpected engine" and kills the process immediately | Extending CEF's C API. Dia generates ObjC bindings from mojom (146 classes, 205 headers) | engine-build.md › Our own code in the tree, review › § B "What Dia does", research `chromium-ui-layer.md` (`2713787d`) › Evidence | Open. Material for comparing which way to lean the FFI with the Rust core (a single JSON surface, or typed bindings generated from mojom). JSON has no types but needs only one surface |
| Keep the core JS API (`WebView`, modules) as it was in the CEF era and swap only the native side | The store and UI can keep moving during the migration. Two app targets are built from the same JS | Rebuild the API too | review › Recommendation 5, ardiacore-spike.md › Migration plan | Adopt (even with a Swift UI, the idea of fixing the boundary between UI and core is the same) |
| On the renderer side, an in-house `ContentRendererClient` + mojom injects page scripts into the main world of every frame, and the `ardia:` scheme is handled by a `NavigationThrottle` | Replaces the process messages and page scripts that CEF provided | — | ardiacore-spike.md › Stage 1 runtime (S4) | Adopt. As a side effect, however, this mojo binding caused every prerender to be cancelled (§ 1.6) |

### 1.3 Window and tab model

| Decision | Reason | Rejected alternatives | Evidence | Applies to Ararat |
|---|---|---|---|---|
| Insert tab views (`WebContentsViewCocoa`) directly into the in-house view tree | Same compositing model as Dia. In the prototype it had the lowest input-to-display latency (p50 15.8–23.3 ms, 120 fps), and a `CABackdropLayer` blur can be applied over web content | OSR (IOSurface → `CAMetalLayer`, 60 fps cap, 42 ms). OWL-style (requires rewiring input, IME, and accessibility) | research `chromium-ui-layer.md` (`2713787d`) › Prototype measurements | Adopt |
| Workspace tabs (unloaded tiles, parked pins, "load when shown") do not hold a `WebContents` | Many tabs in a workspace do not need a live `WebContents` | Make TabStripModel the single source of truth (every tab needs a `WebContents`) | review › Recommendation 1, § B | Adopt |
| Tab views have their own compositor per profile (Chrome has one per window) | A consequence of putting tabs into the in-house view tree | Share a compositor per window (deferred because it means rewriting how tab views are drawn) | perf/vs-browsers.md › Tab switch | Open. The cost is that every tab switch recreates the frame sink and begin-frame source and falls off the vsync grid (§ 1.6) |
| Operations on live tabs are sent as commands (with ids); the engine commits them and returns a transaction with a revision (details in § 1.4) | See below | — | store-api.md › Live tabs | Adopt |
| Peek (temporary tabs) is kept out of Recently Closed and out of Chrome's session (excluded by a hook) | Temporary pages do not push out real history entries | — | engine-build.md › `chromium-temporary-tab-restore-hook.patch` | Adopt (if the feature exists) |
| The session is owned in-house (`session.json`); Chrome's `SessionService` does not track in-house `Browser`s | Avoids double restoration alongside the in-house session | Use Chrome's session restore | engine-build.md › `chromium-hosted-browsers-no-session-service.patch` | Adopt |
| Test instance windows are placed one level below normal and refuse all activation | There was an incident in which a test instance run by a concurrently working agent stole the owner's keystrokes | `open -g` only | agent-brief.md › Rules, testing.md › Test instances | Adopt (if developing with agents) |

### 1.4 Ownership of state

| Decision | Reason | Rejected alternatives | Evidence | Applies to Ararat |
|---|---|---|---|---|
| One writer per fact: the store owns the workspace (order, pins, groups, splits, the shown tab per window); Chrome's `TabStripModel` owns live tabs (which `WebContents` is in which `Browser`, order, active) | During the period when JS guessed at authority in both directions, activation ping-pong occurred (opening 20 tabs caused 230 window updates; opening 12 caused 46–75 switches), and three additional fixes were needed. In one week the mirroring files received 41 commits, 12 of them fixes | Make TabStripModel the single source of truth. Have Chrome ask the app before a change | review › Recommendation 1, § B, store-api.md › Live tabs | Adopt |
| Chrome commits and does not ask the app beforehand | Extension functions (`tabs.update({active})` etc.) change state and read the result back within the same call. Making it an asynchronous query would change what completion means for many callers (the review's first draft was reversed on Codex's point) | Chrome queries the app before a change | review › Recommendation 1, § H | Adopt |
| A transaction is `{rev, cmd, strips}`. `rev` is monotonically increasing; `cmd` is the cause (the id of one's own command, `-1` for one's own engine call, `null` for Chrome's own change). One transaction does not mix causes. On JS restart, start from `tabStrips()` | Eliminates every echo time window, "did I cause this" flag, and timer. A late report does not roll state back | A 1-second echo window and flags | store-api.md › Live tabs, review › Recommendation 1 | Adopt |
| For changes Chrome made by itself (an extension's `chrome.tabs.move`, successor selection after close), the store takes the diff and reflects the same change into the workspace. The successor tab is chosen by the store's rules (split adjacency, skipping collapsed and unloaded tabs), not by Chrome's choice | Chrome does not have the product's rules | Follow Chrome's successor selection | store-api.md › Live tabs, review › § H | Adopt |
| Do not duplicate in in-house JSON the data Chrome already has (history, closed tabs, favicons, zoom, bookmarks, downloads). Keep the in-house UI but place it on top of Chrome's data | Double and triple storage drifted, and the history and bookmarks extensions saw disagreed with the UI. A 1.8 MB JSON was rewritten on every change | Keep the in-house JSON | review › Recommendation 2 (as of 2026-10-01, history, closed tabs, favicons, and bookmarks had been migrated) | Adopt |
| What stays in-house: omnibox ranking and UI, sync (Chrome Sync needs Google), import from other browsers (but the write destination is Chrome's store) | Chrome's importer cannot read Arc or Dia | — | review › Recommendation 2, § E | Adopt |
| For passwords, autofill, extension management, zoom, and search engines, stop scripting hidden chrome:// WebUI via DevTools and call Chrome's services directly from the in-house layer | WebUI private APIs change with each Chromium version, risking settings silently breaking at every bump. Timeouts on hidden pages | WebUI scripting | review › Recommendation 4, agent-brief.md › Stack | Adopt |
| No compatibility branches. The app and engine ship together, so `respondsToSelector`, optional native calls, and old-name aliases are forbidden. The only things kept are versioned on-disk data migrations, versioned sync payloads, and a check that the app/engine API versions match | The only cause of JS/native skew was a shared Metro serving new JS to an old native build | Maintain a compatibility matrix (24 `#if`s and 14 feature macros at review time) | review › Recommendation 3, conventions.md › Backwards compatibility | Adopt |
| Environment variables are read in one place (`ArdiaLaunchConfig`) and passed to the engine as command-line switches. The engine does not read environment variables (3-line exception) | Keeps test spoofing from taking effect in production. `ARDIA_TEST` takes effect only when three conditions hold: a build not signed for distribution, a scratch data dir, and a mock keychain | — | conventions.md › Environment variables, engine-build.md › ArdiaCore's layer | Adopt |

### 1.5 Sync (account-less approach)

| Decision | Reason | Rejected alternatives | Evidence | Applies to Ararat |
|---|---|---|---|---|
| No server, no account, no Apple entitlement. Read and write sealed files in a folder the user chooses (default under iCloud Drive), and let the folder's sync service (iCloud Drive, Dropbox, NAS, USB) carry them | Chrome Sync needs Google. Neither a CloudKit container nor an entitlement is needed | Dia-style server + 6-character pairing code | sync.md top, release-notes 0.2.4 | Adopt (first candidate). But how iPhone and Windows reach the same folder is Open |
| Keys are derived via HKDF from a 24-word BIP-39 recovery phrase (256 bit): a file-key (AES-256-GCM) and a name-key (HMAC-SHA256). The phrase's entropy is stored this-device-only in each Mac's login Keychain and not put in iCloud Keychain. Touch ID or the password is required before the native call that shows or copies the phrase (success valid for 60 s) | The phrase is the key itself. At 256 bit, password stretching is unnecessary. There is no reset path (no one to email) | — | sync.md › Recovery phrase and keys | Adopt |
| Folder and file names are keyed HMACs or random. Content is padded to 1 KiB units and not compressed. AAD binds a file to "folder/name" | Names do not leak profile, site, or kind. Prevents a CRIME-style attack that probes passwords via compression ratio using attacker-chosen page titles. Detects rename, move, and truncation | Compress | sync.md › Threat model, › Folder layout | Adopt |
| Each device only creates new files and never modifies existing ones. Write into a temporary folder on the same volume, then move under `NSFileCoordinator` | Two devices never write the same file, so the sync service has no conflicts. Half-written files are never visible under their real names | Update shared files | sync.md › Folder layout › Writing | Adopt |
| Files are logs (per-device seq-numbered batches of changes) and snapshots (the whole replica + version vector). Merge is a join (commutative, associative, idempotent) deciding per-record last-writer-wins with a hybrid logical clock. Deletion uses tombstones | Converges regardless of file arrival order. Even on a Mac with a lagging clock, an edit made after seeing another device's edit is newer | CRDT trees etc. (not mentioned) | sync.md › Merge | Adopt |
| 3-way: each scope keeps a base (the state right after the last publish or apply), and remote changes are not applied to keys with unpublished edits | Edits made while loading are not overwritten | — | sync.md › Merge | Adopt |
| Before sending, write to a journal (sealed files), then write to the folder. seq is never reused. Quit waits up to 3 s for the save queue | After a crash, the same batch is rewritten with the same bytes. Double delivery is a no-op | — | sync.md › Folder layout › Writing | Adopt |
| Compaction: when there are more than 40 files and no snapshot for 10 minutes, write a snapshot, and delete covered files after 1 hour. Tombstones are kept 45 days (90 days when the version vector has gaps); history 90 days | Snapshots are self-contained, so concurrent compaction is safe | Causal stability (delete tombstones after all devices have applied them). Tried and reverted (`7b334d07`) | sync.md › Compaction | Adopt (the numbers together with the known residual issues). See § 3 |
| Passwords are read from Chrome's password store via the engine, and only values sealed with the sync key are passed to JS. The nonce is an HMAC of login and password (the same password seals identically on every Mac, so it can be compared without opening). If even one row cannot be decrypted, the whole load is skipped | Plaintext never reaches JS. A partial list could be misread as deletions | Chrome's `passwordsPrivate` (requires device authentication every time) | sync.md › Passwords | Adopt |
| Extension sync covers the same set as Chrome Sync (those the user installed from the Web Store). Install without specifying a version; if there are permission warnings, install disabled, and enable only when the version and permissions match those approved on another Mac. Removal is not a tombstone but a live value `{removed: true}` | Chrome's updater grants the fetched version's permissions as is. Tombstones get erased by compaction and by old Macs | — | sync.md › Extensions | Adopt |
| New record kinds are added under prefixes that older versions do not read, so older versions neither delete nor write them back (`pth:`, `share:`, `pgc:`, `pord:`, `pgh:`) | A nightly Mac syncs with a stable Mac one version behind. Only the sync payload carries versioned compatibility | Add fields to existing records (older versions write them back and drop them) | sync.md › What syncs table, conventions.md › Backwards compatibility | Adopt |

### 1.6 Memory and performance

| Decision | Reason | Rejected alternatives | Evidence | Applies to Ararat |
|---|---|---|---|---|
| Tab sleep is ultimately left to Chrome's Memory Saver (enabled by default; Moderate / Balanced / Maximum; sites always kept active) | In-house sleep and Memory Saver conflict (the reason Helium's patch making Memory Saver the default had been skipped). Since in-house sleep is dropped, the patch was re-applied | Keep the in-house tabLifecycle (review Recommendation 2 had said "policy in-house, with Chrome's discard as an input") | commit `1af72e64`, release-notes 0.2.43-nightly.4 | Adopt. History in § 2 |
| Add Ardia-specific parameters to background tab freezing (`InfiniteTabsFreezing`): frozen tabs that have never opened WebSocket, WebTransport, or WebRTC are thawed every 10 minutes; tabs that have opened one are not frozen | Chrome's freezing drops WebSockets. Chrome thaws for 5 seconds every minute, and YouTube was using 3.35 mW | Chrome's default | engine-build.md › `chromium-thaw-live-connections.patch`, perf/vs-browsers.md › Power | Adopt |
| Enable `ThrottleMainFrameTo60Hz` (main frame 60 Hz, compositor 120 Hz) and add a patch that returns to full rate for 1 second after showing, during scroll, and for 1 second after input | On a YouTube watch page, renderer power went 79 → 54 mW. ## 3. What Ararat should avoid from the start

- **Do not go through CEF.** CEF conflicts structurally in three places (windows, tab creation, run loop), and 77% of patch lines were spent only on passing Chrome objects through CEF's API (review › Recommendation 5, § C). The spike ran 2 profiles, 1 window, popups, autofill, DevTools, and MV3 extensions with an in-house layer of about 3,200 lines (ardiacore-spike.md › Verdict).
- **Do not plan a gradual coexistence of CEF and an in-house framework.** Two Chromiums cannot go into one process (ardiacore-spike.md › Codex second opinion).
- **Do not put two writers on tab state.** The workspace belongs to the core, live tabs belong to Chrome, connected by commands + transactions with revisions. Do not create echo time windows or "did I cause this" flags (review › Recommendation 1, store-api.md › Live tabs).
- **Do not design Chrome to ask asynchronously "may I change this".** It breaks the meaning of synchronous completion for extension functions (review › § H).
- **Do not duplicate in the core data that Chrome already has.** For history, bookmarks, favicons, closed tabs, zoom, and downloads, put the UI on top of Chrome's services (review › Recommendation 2). What goes in the Rust core is limited to what Chrome does not have (workspace, sync, import).
- **Do not manipulate settings by scripting chrome:// WebUI.** It silently breaks on every version bump (review › Recommendation 4).
- **Do not write patches that heavily rewrite Chrome's files.** Use new files + function-pointer hooks declared in a shared header, and put the `series` and the byte-comparison check in place from day one (engine-build.md › Our hooks, › The patch series).
- **Do not build an in-house policy that runs alongside Chrome's tab sleep and freezing mechanisms.** Ardia rebuilt it 4 times in 10 days and finally went back to Memory Saver (§ 2, commit `1af72e64`). Add any needed tuning as parameters of Chrome's mechanisms (in the form of `chromium-thaw-live-connections.patch`).
- **Do not put a UI framework round trip into the tab display path.** Tab switch and new tab display waited for a React commit and took 40 ms versus Chrome's 8 ms (perf/vs-browsers.md). Make gesture and motion native from the start too (research/profile-swipe-native-controller.md).
- **Evaluate at design time the cost of recreating a compositor per tab view.** Each show takes 1–2 refreshes to start the display link (perf/vs-browsers.md › Tab switch). Moving to per-window sharing later means rewriting drawing.
- **Do not create any path that writes into the app bundle.** Point the extension DNR index, code sign clones, etc. at the data dir, and re-verify the signature after launch before release (engine-build.md › Nothing writes into the app bundle).
- **Do not change the Safe Storage keychain item name later, and do not silently recreate the key.** Every user's passwords and cookies become unreadable (engine-build.md › `chromium-safe-storage-*`, release-notes 0.2.40).
- **Do not let the base patch set decide the licence.** The moment Helium's patches were taken in, the entire distribution became GPL-3.0 (engine-build.md › Licence and source). Decide the choice of base (ungoogled is BSD-3-Clause, Helium is GPL-3.0) first, as licence policy.
- **Do not ship with Safe Browsing compiled out and no replacement decided.** The absence of phishing/malware URL checks and download evaluation is called the biggest unresolved gap (issue #249).
- **Do not postpone how DRM is handled.** Widevine requires Google's VMP signing, and Ardia worked around it with a second WebKit engine (release-notes 0.2.41, engine-build.md › GN args).
- **Do not rely on wall clock for tombstone collection in sync.** Put into the design from the start the requirements shown by the causal stability attempt (reverted in `7b334d07`): (1) count writers whose files have not yet arrived, (2) do not delete the base the adapter relies on when a device rebases, (3) store the device incarnation together with the journal, (4) a device restored from backup must not reuse its incarnation and seq (sync.md › Compaction). The known residual issue of the current approach is that a log arriving after 45 days (90 days if there are gaps) brings back deleted records.
- **Do not extend the sync record format in a way that older versions write back and break.** Add new information under keys older versions do not read (sync.md › What syncs).
- **Do not tolerate a mismatched core through compatibility branches.** Ship the app and the core together, with a single API version match check (conventions.md › Backwards compatibility).
- **Do not gate performance regressions on wall-clock alone.** ±20% jitter causes false alarms. Use a count ratchet and alternating control/candidate runs (perf/README.md).
- **Do not introduce caches or prewarm without staleness tests** (perf/sprint.md › Lessons).
- **Do not add more agents while engine builds cannot be parallelized.** A single chromium lock serialized all engine work (review › § F).
